# QookiX Launcher — UI 全局一致性扫描报告

扫描范围：`src/**/*.vue`（75 个组件 + 16 个页面） + `src/styles/*.css`
对照基准：`docs/ui-design-guideline.md` §3 令牌 / §4 骨架 / §5 组件 / §6 网格

> 本文件是**当前状态快照**，不是历史记录。每轮改造后直接改数值，不要追加「第 N 轮」章节。
> 最近一次：2026-11-14（第二轮：全局收口）。

---

## 一、结论

第一轮把令牌层（`tokens.css`）和共享类层（`components.css`）建起来了，但页面基本没接入 ——
「不统一」不是漏改几处，而是**每页各写各的**。第二轮把这些「各写各的」按可见度重排后逐个收口，
指标变化如下：

| 指标 | 第一轮 | 现在 |
|---|---|---|
| 字号走令牌 | 1.3% | **94%**（1001 → 59 处字面量） |
| 圆角走令牌 | — | **99.8%**（482 → 1 处） |
| 动效走令牌 | 4% | 20%（存量未动，低优先） |
| 卡片网格 `minmax` 取值 | 17 种 | **5 种**（320 / 280 / 200 / 96 + 2 个固定矩阵） |
| `.mini-btn` 局部副本 | 17 份 | **0** |
| 弹窗宽度取值 | 10 种 | **4 档**（420 / 560 / 680 / 780） |
| 硬编码主题色 | 62 处 | 45 处（其中 22 处是 `tokens.css` 自身定义，其余是 `var(--accent, #xxx)` 兜底与调色板数据） |

## 二、这一轮改了什么（按「用户能不能看出来」排序）

### 1. 内容宽度：取消所有上限，跟随窗口

**结论先后变过一次，以此为准**：最初的做法是「统一宽度上限」——给缺上限的页面补 1120，
并在 `.qx-page` 上保留 `max-width: 1120px`。落地后判断这是错的方向：

- 宽屏下内容锁在 1120，右侧空出一大片，视觉上更像个网页而不是桌面应用；
- 「哪页加上限、哪页不加」本身又是一条需要自觉遵守的规则，等于用一个新的一致性负担换旧问题。

最终处理：**`.qx-page` 去掉 `max-width` 与 `margin: 0 auto`，全站内容宽度跟随窗口、左对齐**；
`HomeView` 吸底卡自带的 1120 上限与 auto 外边距一并移除（否则会比上面的网格窄一截）。
中途加的 `.qx-page-width` 轻量骨架已删除，不再保留。

> 教训记一笔：一致性不等于「统一成一个固定的窄宽度」。宽度这类受窗口影响的量，
> 用「都不限制」比用「都限制成 1120」更稳，也少一条要维护的规则。

### 2. 按钮族：17 份 `.mini-btn` → 1 份

同一颗小按钮原来有 6 种 padding、3 种圆角、高度 24–34 不等，并排时高度对不齐。
现在只在 `components.css` 定义一次（= `sm` 档 28px），变体补全 `primary / cta / danger / active / icon-only / solid`；
页面里的 17 份副本全部删除，模板里 `play / cloud / accent` 这类自造变体统一改名。

顺带修掉两处「主次颠倒」：`.primary` 从「7 个文件里 6 个是描边款、1 个是渐变款」统一为**描边款**，
整块渐变只留给新增的 `.cta`（区块主操作）。

### 3. 输入框：4 份 `.text-input` → 1 份，高度对齐按钮

设置页 / 按键页 ×2 / 实例设置各写一份，圆角 8 与 10 并存，高度靠 `padding: 8px 12px` 撑到 36 —— 比旁边的 32px 按钮高 4px。
现在统一为 `.qx-input, .text-input`：32px 高 / radius 10 / `--w-06` 底，focus 给 `--accent-50` 描边 + 2px 光晕。

顺带修掉一个真 bug：三处局部 `.text-input:focus` 把描边改成 `--accent-05`（5% 透明度），
实际等于**没有 focus 反馈**，比不写还差。

### 4. 卡片：`.qx-card` 不再比 `.glass` 多一条边

`.qx-card` 原来带 `1px solid var(--border)` + `--card-shadow`，而全站 6 个真实卡片类都是无描边无投影 —— 照着规范用反而更不合群。
现在对齐 `.glass`；需要边界时显式加 `.qx-card--outline`。

同类收口：

| 卡片 | 改前 | 改后 |
|---|---|---|
| `.p-card`（项目 / 拾木帖） | padding 14 / gap 12 | 18 / 14（与实例卡同档） |
| `.tool-card`（工具箱） | **无 hover 反馈** | 补 `--card-shadow-hover` |
| `.recent-card`（投影 / 材质预览） | 两份：12/10 与 14/10 | 12 / 10 / 13px 标题 |
| `.skin-card` | radius 11 / `--w-03` | radius 10（`--w-03` 保留，属"卡片内次级块"） |

### 5. 主题色：换色后不再残留琥珀

`InstallChecklist`（Material 色系绿/蓝/橙）、`VersionPicker`（release/beta/alpha）、
`SettingsTab` / `SettingsView` 的内存仪表、`IconPickerDialog`、`CodeEditor`、`TimeMachine` 的 hero 徽章 ——
原来写死 `#e89a4b` / `rgba(232,154,75,…)`，用户把主题换成红色时这些地方仍是琥珀。

现在全部走 `--accent*` / `--success` / `--info` / `--danger` / `--warn`。
`CodeEditor` 还顺手去掉了局部 `--accent: #e89a4b` 的覆写（编辑器从此跟随主题色）。

> 仍保留字面量的只有两类，都是**故意**的：`InstancesView` 的分组调色板、`SettingsView` 的主题色预设列表 —— 它们是「可选颜色数据」，不是主题色的使用方。

### 6. 字号 / 圆角：机械收编

- 字号：1001 → 59 处字面量，且**取值不变**（9/10/11→`--fs-2xs`，12→`--fs-xs`，13→`--fs-sm`，14→`--fs-base`，15→`--fs-md`，20→`--fs-lg`，26→`--fs-xl`）。
- 圆角：482 → 1 处，19 种取值并按 6 档标度就近归并（差值 ≤2px）。
- 剩下的 18 / 16 / 22 / 34 / 36 / 46px 多数是**图标尺寸**（`font-size` 给 svg 定尺寸）与装饰性大数字，不要再强行并入字号档位。

### 7. 骨架与层级

- 页面标题**不强制**。中途给工具箱页补过 `.qx-page-head`（标题 + 副标题），按实际判断已回退 ——
  以内容为主的页面直接铺内容，不当成「缺了一块」。
- 详情页主标题 21px → 20px（出现标题时与 `.qx-page-title` 同档）。
- 空状态：4 份 `.empty` 的内边距（48/20、44/24）与说明色（`--text-2` vs `--text-3`）对齐到 `.qx-empty` 那一套。
- 浮层阴影 9 处硬编码 → `--layer-shadow` / `--pop-shadow`（浅色主题会自动换更柔的一套）。
- 弹窗宽度 10 种 → 4 档（≤480→420，≤600→560，≤700→680，>700→780）。

## 三、仍然存在的不一致（按性价比排序）

| # | 问题 | 量级 | 建议 |
|---|---|---|---|
| 1 | naive-ui 控件 `size="small"` 85 处 vs `size="medium"` 5 处 | 高度 28 | 实际标准已是 small。要么全局把默认 size 设成 small 并删掉逐个传参，要么反过来统一 medium；**别维持现状**——同一行里 28 的 select 和 32 的 input 基线不齐 |
| 2 | 提示条 `.hint` 9 份实现、`.qx-hint` 只有 3 处使用 | 中 | 先分清「提示条（有底色 + 左侧色条）」与「说明文字（纯 `--text-3` 小字）」，只有前者该收进 `.qx-hint` |
| 3 | 徽章 23 个自造（`.chip` / `.tag` / `.pd-cat` / `.guest-badge` …） | 中 | 统一到 `.qx-badge` + 语义变体 |
| 4 | 动效时长仍是字面量（204 处 `0.15s ease` 之类） | 大 | 只在新代码强制令牌；存量按「同一个组件内统一」逐步替换 |
| 5 | `.btn` 自建体系仍有 3 处（ContentTab / ServerDetailView / TimeMachineView） | 小 | 与 `.mini-btn` 同样的处理：先合并变体语义，再删局部定义 |
